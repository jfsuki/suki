❌ TC01 original: "el LLM genera un SDD (Software Design Document)"
✅ CORRECCIÓN: SUKI NO genera SDDs. El agente hace una entrevista
   estructurada y produce un JSON schema guardado en
   project/storage/apps/{tenant}/{appId}.json. El output medible es
   ese archivo + las tablas MySQL creadas.

❌ TC02 original: "Interceptar el prompt generado antes de ir al LLM"
✅ CORRECCIÓN: En SUKI el system prompt NO es generado — es inyectado
   desde AppMemoryService::buildDeveloperContext(). Lo que se testea es
   que ese contexto se incluye correctamente en la llamada LLM.

❌ TC06 original: "APIs de generación de UI"
✅ CORRECCIÓN: SUKI NO genera código UI. Usa vistas PHP pre-construidas
   + JSON contracts. No hay "generación de UI" en el scope.

❌ TC08 original: "Creación de Automatizaciones (Estilo n8n)"
✅ CORRECCIÓN: NO IMPLEMENTADO. Mover a backlog post-producción.
   No incluir en pruebas de esta iteración.

❌ TC10 original: "dashboard de AgentOps"
✅ CORRECCIÓN: El Control Tower Dashboard (Torre) no está completado
   (SPRINT_TRACKER S6.A-F = 0% iniciado). Usar la API directa:
   GET /api/chat/journal/get y GET /api/chat/quality.
